# Checkout Abandonment Tracking Implementation

## Overview
Track users who show interest in checkout but don't complete their order by monitoring form activity state and sending their data via GTM when they become inactive.

## Tasks

### 1. Form Activity State Tracking
- [ ] Add state to track if form is "active" (user is interacting) vs "inactive" (user abandoned)
- [ ] Detect user activity through:
  - `onFocus` events on form inputs
  - `onChange` events during typing
  - Mouse movement within form container
  - Scroll activity
- [ ] Set inactivity timeout (e.g., 30 seconds) after last interaction
- [ ] Only track if user has entered any form data but hasn't submitted

### 2. GTM Integration for Interested Users
- [ ] Import `trackUserCheckoutData` from `@/lib/gtm`
- [ ] Call `trackUserCheckoutData` when:
  - User triggers inactivity (abandonment)
  - Form has some data filled but order wasn't submitted
  - Only send if user has entered meaningful data (e.g., at least email or phone)
- [ ] Include form data: email, fullName, phone, address, city, country, note

### 3. Implementation Points in Checkout Page
- [ ] Add refs to track activity timer
- [ ] Add `onFocus`, `onChange` handlers for inputs to reset activity timer
- [ ] Add cleanup to prevent double-tracking
- [ ] Use localStorage to flag if tracking was already sent (prevent duplicates on page revisit)

### 4. Edge Cases
- [ ] Don't track if order was successfully placed
- [ ] Don't track if user hasn't entered any data
- [ ] Clear tracking flag on successful order
- [ ] Handle page refresh/beforeunload scenarios
